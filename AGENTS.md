# ReviewTrust engineering guidance

Build an evidence-based electronics review-pattern analyzer, never an authenticity authority. Stack: Next.js App Router/React/TypeScript/Tailwind and Python FastAPI/Pydantic/Uvicorn. Offline ML only when justified; no database, accounts, paid LLM, URL fetching or browser extension in v1.

Read this file, SPEC.md, README.md roadmap and docs/HANDOFF.md before each step; inspect Git status/branch/recent commits and relevant files. Preserve existing user work. Implement exactly one approved roadmap step per user message. Completed: Steps 1–8; next pending: Step 9. Do not start until user says `next`.

SPEC.md owns contracts, scoring, evidence definitions and acceptance criteria. docs/THREAT_MODEL.md owns proposed controls. docs/DECISIONS.md records tradeoffs. Numeric scoring is experimental; missing evidence is never low risk; no confidence level without validation. No review names, raw-body logs or persisted uploads. Treat all input as untrusted.

Prefer small pure analysis functions, explicit typed API contracts, deterministic evidence and native/standard-library features. Server limits and validation are authoritative. Add dependencies only for concrete needs. Review methodology changes with a version bump and regression fixtures.

Foundation: `web/app/page.tsx` stays synchronous and composes the client Analyzer; browser input/results are implemented. FastAPI serves GET / development status, GET /health and POST /v1/analyze (JSON), /v1/analyze/csv (multipart). `ml/` holds the offline source audit, labelling rubric and bounded synthetic audit/split tool; no real dataset is admitted. Runtimes: Node 24 and Python 3.12. Install with `npm --prefix web ci` and the pinned `api/requirements-dev.txt` in `api/.venv`. Do not add ML dependencies before justified evaluation work.

Input contracts live in `api/app/schemas.py`; use `parse_json`/`parse_csv` from `api/app/ingestion.py` for untrusted bytes and `ReviewInputError` for safe public details. Never expose raw Pydantic errors or submitted unknown keys. See docs/INPUT_VALIDATION.md. Decimal rating bounds are checked before float conversion. Keep duplicate rows and request-local references. Library records are raw; `analysis.py` masks common emails/phones before matching/output and `security.py` enforces HTTP boundaries. Masking is incomplete; the UI must request removal of personal information and render returned review text safely.

Step 4: explicit result/error schemas in `results.py`; callback-only bounded multipart in `uploads.py`, no UploadFile or disk spooling. Current methodology rt-patterns-0.2.0-experimental includes exact/TF-IDF repetition and four incentive phrases as scoring signals; timing, rating distribution and lexicon disagreement are contextual only. Preserve score gates, max aggregation, exact half-up rounding and unset confidence. signals.py holds pure signal functions; SPEC.md defines tokenizer/IDF, feature-cap withholding, thresholds, UTC windows and lexicon abstention. Keep deadline checks and bounded evidence. Endpoint/config details are in docs/API.md. Environment configuration does not auto-load .env. Retain single-process admission/hashed token-bucket controls, no-proxy-headers development command and worker slot retention on cancellation; production proxy/provider auditing remains pending. Only fixed error codes/request IDs may be logged on unexpected failure.

Verification: from repository root on Windows, run `./scripts/check.ps1`. Backend commands from `api/`: `.venv/Scripts/python.exe -m pip check`, `-m pytest`, `-m ruff check .`, `-m ruff format --check .`. Offline from root: `api/.venv/Scripts/python.exe -m unittest discover -s ml/tests -v`, plus Ruff check/format on ml with `--config api/pyproject.toml`. Frontend from root: `npm --prefix web run test`, `run lint`, `run typecheck`, `run build`. On Unix use `.venv/bin/python`. Run API with `./scripts/dev-api.ps1` and web with `npm --prefix web run dev`; both bind loopback. CI mirrors checks on Ubuntu; local passing checks are not a claim that remote CI ran.

Known tooling constraint: eslint-config-next's bundled React/import/accessibility plugins require ESLint 9, which emits an upstream deprecation warning. Keep compatible pins and revisit D15 before deployment; do not force invalid peer resolutions. Next.js creates `web/AGENTS.md`; preserve its framework guidance. Generated next-env.d.ts, build output and virtual environments are ignored. Never log raw reviews or add real user data to tests.

Step 7: ml/audit.py is a separate standard-library offline workflow, not a public ingestion route. Read docs/DATASET_AUDIT.md, docs/LABELLING.md and ml/README.md before research work. sources.json admits only synthetic-fixture-v1; real candidates remain not_approved and training_authorized is always false. Freeze exact bytes/source-card/seed/connected-product-and-duplicate groups/test IDs in manifests; never chunk or silently truncate for splits, fit vocabulary on held-out data, relabel proxies as deception, or reroll a seed for favourable balance. Real data/derived hashes need permission/privacy review and remain ignored; only authored synthetic examples/manifests are committed. Step 8 explicitly chose the no-train path; reopening training requires new admissible evidence resolving scope, rights and target validity.

Step 8: docs/MODEL_CARD.md records NO TRAIN; no independent admitted electronics deception target exists in the recorded audit. ml/evaluate.py runs the production heuristic baseline on 17 authored mechanical cases, verifies the Step 7 freeze, and binds a frozen report to catalog/implementation hashes. Run `api/.venv/Scripts/python.exe -m ml.evaluate --verify ml/fixtures/mechanics.expected.json`. Do not translate fixture pass counts into classifier accuracy or populate unavailable precision/recall/F1/confusion-matrix/calibration fields. No trained model or confidence level is justified. Review report differences intentionally when implementation changes; the evaluator has no training override. Step 9 must preserve these limits in presentation.
